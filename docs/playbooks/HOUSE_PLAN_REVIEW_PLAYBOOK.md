# 평면도 검토·수정 플레이북 (저성능 AI용 결정 규칙)

실사례: `Drawing2.dwg` 단독주택 1층 평면도(X 63700~75900, Y 9900~18500), 2026-09-29.
실행 데이터: [`house_plan_fix.plan.json`](house_plan_fix.plan.json) · 실행기: [`scripts/com_plan_runner.py`](../../scripts/com_plan_runner.py)

> 핵심 교훈: **"문제점 보고서"를 그대로 실행하지 않는다.** 이번 보고서 8개 항목 중 실제 결함은 3종류뿐이었고,
> 나머지를 그대로 수행했다면 도면이 망가졌다(예: 열린 벽선을 CLOSE → 방을 가로지르는 대각선 생성).
> 모든 항목은 아래 **검증 절차**를 통과한 것만 수정한다.

## 0. 도구 선택

**먼저 `cad_status`의 `commands`를 본다.** `delete`·`transform`·`snapshot`이 있으면 0.3.0 이상 → MCP만으로 작업한다.
없으면 0.2.0 → 아래 표의 COM 열로 폴백. (서버만 새 버전이면 새 도구가 `PLUGIN_OUTDATED`를 돌려준다: AutoCAD를 닫고
`scripts/install_autocad_plugin.ps1` 재실행 후 AutoCAD 재시작.)

| 작업 | MCP 0.3.0 (실기 검증 2026-09-29) | 0.2.0일 때 COM 폴백 (`com_plan_runner.py`) |
| --- | --- | --- |
| 조회 | `cad_query`, `cad_get`, 치수 포함(`types:["DIMENSION"]`) ✅ | `--dump-dims x0 y0 x1 y1` |
| 도면 자원(스타일·블록·범위) | `cad_inspect` ✅ | – |
| 레이어 조회·생성·색/선종류 | `cad_layers`, `cad_set_layer` ✅ | – |
| 생성: 선·폴리선·원·호·문자(정렬)·MTEXT·점 | `cad_create` ✅ | – |
| 생성: 치수(rotated/aligned) | `cad_create {type:"dimension", p1, p2, offset, style}` ✅ | `add_dimension` op |
| 생성: 해치 | `cad_create {type:"hatch", points, pattern, scale}` ⚠️ 아래 주의 | – |
| 삭제 | `cad_delete` ✅ | `delete` op |
| 이동·복사(배열) | `cad_move`, `cad_copy` ✅ | – |
| 회전·축척·대칭 | `cad_transform` ✅ | `scale` op |
| 색·레이어·문자 높이·정렬 변경 | `cad_set_properties` ✅ | – |
| 문자 내용 변경 | `cad_replace_text` ✅ | `set_text` op |
| 폴리선 합치기(벽 접합부) | `cad_batch` [create 합친 윤곽 + delete 원본들] ✅ | `replace_polylines` op |
| 결과 눈으로 확인 | `cad_snapshot {window}` ✅ (요청 영역 그대로 PNG) | – |

주의 (실기 검증에서 나온 것)
- **여러 단계를 한 번에 → `cad_batch`.** 한 단계라도 실패하면 전체가 롤백된다(검증함). 오류 메시지에 `steps[i]`가 나온다.
- **`expect_fingerprint`를 꼭 넣는다.** 틀리면 `STALE_TARGET`으로 거부된다(검증함) → `cad_get`으로 다시 읽고 재시도.
- `cad_create`에서 해치 경계는 `points`(닫힌 다각형 꼭짓점)다. `boundary`가 아니다. 모르는 인자는 `INVALID_PARAMS`로 허용 목록을 알려 준다.
- **해치:** 한 `cad_create`에 해치를 섞지 말고 따로 만든다. 해치가 실패하면 같은 호출의 다른 개체도 모두 롤백된다.
  오류에 `hatch pattern` / `hatch boundary` 단계가 표시된다.
- **치수 스타일:** `ISO-25`처럼 축척 1인 스타일은 mm 도면에서 글자·화살표가 거의 안 보인다. 도면 축척에 맞는
  스타일(예: `80` = 1/80)을 `cad_inspect sections:["dim_styles"]`로 찾아 `style`에 지정한다.
- **`cad_snapshot`은 도면을 바꾸지 않는다.** 수정할 때마다 전후 스냅샷을 찍어 사용자에게 보여 준다.

COM 폴백을 쓸 때의 작업 순서: ① 계획 JSON 작성 → ② `python scripts/com_plan_runner.py PLAN.json` (검증만) →
  ③ `ok:true` 확인 후 `--apply` → ④ `cad_get`으로 새 핸들을 **MCP로 교차 확인**.
  모든 op는 한 UNDO 그룹이므로 AutoCAD에서 `UNDO` 1회로 전체 되돌림.
- **도면은 저장되지 않는다.** 적용 후 사용자가 저장하기 전에 AutoCAD가 꺼지면 수정이 사라진다 → 적용 직후 사용자에게 저장(`QSAVE`)을 요청.

## 1. 항목별 판정 규칙

각 규칙은 "보고된 증상 → 확인할 데이터 → 판정"이다.

### R1. "폴리선이 닫히지 않음(closed=false)" 
- 확인: 열린 폴리선의 **양 끝점이 무엇에 닿는지** 조회(`within` ±60).
- 끝점이 다른 벽면선(CON 등) 위 또는 문틀(DOOR) 위에 있으면 → **정상**. 이중선 벽의 한쪽 면이다.
- 두 선의 간격이 일정(예: 100)하고 평행이면 → 벽 두께 정상.
- ❌ 절대 CLOSE 하지 않는다: 시작점과 끝점을 잇는 대각선이 방 안에 생긴다.
- 이번 사례: WAL1 `7C1`/`7C2`(기존 근린생활시설 영역) — 시작점이 CON 선 `7A3` 위, 끝점이 문틀 `7CA`. 판정 **오탐**.

### R2. "벽이 토막 사각형으로 분리됨"
- 개구부(창·문) 사이 벽을 **각각 닫힌 사각형**으로 두는 것은 정상(해치 가능, 개구부는 끊겨야 함).
  "외벽 전체를 폴리선 1개로" 는 개구부 때문에 불가능 → 오탐.
- **진짜 결함은 모서리/T자 접합부**다. 확인 방법:
  1. 벽 중심선(CEN) 교차점마다 벽 두께 정사각형(예: 100×100, 200×200)이 어느 폴리선에 덮이는지 계산.
  2. **아무 폴리선도 덮지 않으면 → 빈 모서리(구멍)**. 반드시 수정.
  3. 두 폴리선이 모서리를 나눠 덮어 벽 두께를 가로지르는 **이음선**이 생기면 → 합쳐서 ㄱ/ㄷ/T자 1개로.
- 수정: `replace_polylines` — 원래 폴리선 좌표를 `expect`에 전부 적고, 합친 윤곽을 `new`에.
  합친 윤곽 좌표는 **반시계/시계 한 방향으로 외곽을 따라** 적는다. 인접한 문틀 끝점(X 좌표)이 그대로인지 확인.
- 재질이 다른 벽(CON 외벽 ↔ WAL1 칸막이)의 접합선은 **남긴다**(재료 경계 표시).
- 이번 사례에서 수정한 7곳:

| id | 위치(중심선) | 증상 | 조치 |
| --- | --- | --- | --- |
| IW-67700 | 안방 우상단 X67700×Y14200 | 100×100 **빈 모서리** | ABA+AB1 → ㄱ자 |
| IW-72200 | 침실2 좌상단 X72200×Y14200 | 100×100 **빈 모서리** | ABB+AB2 → ㄱ자 |
| IW-66800 | X66800×Y15400 | T자 이음선 2개 | AB5+ABC+AB6 → T자 |
| IW-68900 | X68900×Y15400 | ㄱ자 이음선 | AB7+ABD → ㄱ자 |
| IW-74000 | X74000×Y15400 | ㄱ자 이음선 | ABF+AB8 → ㄱ자 |
| CW-L | 좌측 외벽 | 모서리 이음선 2개 | AA4+AAE+AA8 → ㄷ자 |
| CW-R | 우측 외벽 | 모서리 이음선 2개 | AA7+AAF+AAD → ㄷ자 |

### R3. 미서기창
- 표현 규칙(이 도면 기준): 벽면선 2줄(WINELE, 벽 두께 간격) + 창틀(WINBAR, 60폭) + 창짝 2개(WIN, 각 20 간격 2줄, 서로 어긋나게).
- WIN(20 간격)과 WINELE(200 간격)은 **서로 다른 것**(유리 vs 벽면선) → "이중 유리선" 판정은 오탐.
- 창짝 겹침 100mm는 평면 기호로 통상 범위(실제 미서기 겹침 50~100). 200으로 늘리는 것은 근거 없음 → 수정 안 함.
- 미서기창에는 중간 방틀(WINBAR)이 없다 → "중간 WINBAR 누락"은 오탐.
- "창짝 분할 누락" 판정 전에 **WIN 레이어를 먼저 조회**할 것. 이번 사례 상단 창(64760~65840)은 WIN 4줄로 이미 2짝 → 오탐.
  폭 480 욕실창(WIN 1쌍)은 고정/단창 → 정상.

### R4. 도곽 위치
- 블록 삽입점은 **도곽의 좌하단 모서리**다. 삽입점과 도면 좌표를 비교하지 말고 **bbox 안에 도면이 들어가는지**를 본다.
- 이번 사례: 삽입점 X50005은 도면(X63700)에서 13700 떨어져 있지만 도곽 bbox 50005~92005가 도면을 포함 → "이격" 판정 **오탐**.

### R5. 축척 (진짜 결함)
- 확인 3가지를 **서로 비교**한다: ① 치수스타일 이름/DIMSCALE(`--dump-dims`의 `style`), ② 도곽 블록 배율, ③ 도곽 축척 문자.
- 이 도곽 블록(`ZIUM_sheet_architect`)의 원본 크기 = 84000×59400 = **A1 × 100**. 따라서
  `배율 = (A1→A3이면 0.5) × (축척분모 / 100)` → A3 1/100 = 0.5, **A3 1/80 = 0.4**, A3 1/60 = 0.3.
  (보고서의 "1/80 → 0.8"은 틀림. 0.8은 A1 1/80.)
- 이번 사례: 치수 24개가 스타일 `80`(DIMSCALE 80) ↔ 도곽 0.5(1/100), 문자 "1 / 100" → **불일치**.
  1/60(A3 0.3)은 도면영역 21150×16320에 평면+치수(약 19400×18200)가 안 들어가 불가 → **1/80 채택**.
- 조치: 도곽 + 도곽 밖에 따로 놓인 제목 문자·번호 원/선(F9E~FA7, 11개)을 **같은 기준점에서 같은 비율로** `scale`
  (0.5→0.4 이므로 factor 0.8, 기준점 = 도면 중심 부근 (69700,14500)), 축척 문자 2개 `set_text`.
- 축척 후 반드시 확인: 도곽 내부 도면영역(원본 4000~74499 × 2000~56400 × 배율 + 삽입점)이 치수 문자까지 포함하는지.

## 2. 보고 형식

사용자에게 항목마다 **수정함 / 오탐(근거) / 보류(사용자 판단 필요)** 중 하나로 답한다. 오탐은 조회한 핸들·좌표를 근거로 제시.

## 3. 사고 대응 (이번 세션 실제 발생)

- 적용 직후 AutoCAD가 재시작되어 `Drawing2.dwg`(미저장)에 대한 연결이 끊겼다. `cad_status`→`NOT_CONNECTED`,
  COM `GetActiveObject`→`MK_E_UNAVAILABLE(-2147221021)`.
- 재연결 후 할 일: `cad_query`로 새 핸들 `11F0~11F6`, 도곽 `F9D` 배율 0.4 존재 여부 확인.
  없으면 도면이 적용 전 상태(또는 자동저장본)로 돌아간 것 → `com_plan_runner.py PLAN.json` 검증을 다시 돌린다.
  검증이 `ok:true`면 원래 상태이므로 `--apply`로 재적용 가능(계획이 핸들+좌표로 고정되어 있어 다른 상태에는 적용 거부됨).

## 4. 표준 미서기창 형태 (좌측 도곽 원본 → 우측 단독주택 7곳 적용, 2026-09-29)

원본: 좌측 도곽 창 X 26121~26821 × Y 23876~24076 (핸들 847~859, 벽 200, 창폭 W=700).
다른 폭에는 아래 **공식**으로 그린다. 좌표는 (창 좌측 벽 끝, 외부측 벽면) 기준 `(x, y)`, `W`=개구부 폭, 벽 두께 200,
창틀 깊이 125는 벽 중앙(`o = 37.5`)에 둔다. `m = W/2`. 외부가 위쪽인 벽(상단 외벽)은 `y → 200 − y`로 뒤집는다.

| --- | --- | --- |
| 벽면선 2줄 | ELE | (0,0)–(W,0), (0,200)–(W,200) |
| 좌 문틀 | WINBAR | 닫힌 폴리선 (0,o) (0,125+o) (44,125+o) (44,119.5+o) (23,119.5+o) (25,6+o) (53,6+o) (53,o) |

적용 절차(한 창당 `cad_batch` 2단계): ① 기존 창 부재(WINBAR/WINELE/WIN) `delete`(지문 고정) → ② 위 부재 17개 `create`.
7개 창 = 14단계, 한 번의 `cad_batch`로 원자 적용. 먼저 `dry_run:true` → 스냅샷으로 원본과 나란히 비교 후 적용.
실수 사례: 처음에 문틀을 벽 두께 전체(200)로 늘리고 벽면선을 WINELE로 그려 원본과 달라졌다 → **원본을 `cad_query`로 전부 읽고
레이어까지 맞출 것.** 원본의 벽면선은 ELE 레이어다.
